# Liam McBride — Portfolio Site

A static, no-build-step site: 4 HTML pages + one shared stylesheet + one shared
JS file. No framework, no npm install — this is intentional, so GitHub Pages
can serve it directly with zero configuration.

## File structure

```
portfolio-site/
├── index.html      Home — hero + featured projects
├── about.html       Bio, education timeline, skills, publications
├── projects.html    All 5 planned projects, filterable by tag
├── contact.html      Contact form (mailto-based) + direct links
├── style.css         Shared design tokens + all styling
├── main.js           Shared nav/footer injection, hero animation, filtering
└── resume.pdf        ← add your résumé PDF here (referenced from index.html)
```

Header and footer aren't duplicated in every HTML file — `main.js` injects
them into `<header id="site-header">` and `<footer id="site-footer">` on
page load, and highlights the current page in the nav automatically. Edit
the nav links or footer content once, in `main.js`, and every page updates.

## Before you deploy

1. **Add `resume.pdf`** to the project root (or update the link in
   `index.html` if you'd rather host it elsewhere).
2. **Replace `yourname`** — search all files for `github.com/yourname` and
   swap in your real GitHub username (used in the footer and every project
   card's "GitHub →" link).
3. **Fill in real project links** as you finish each of the 5 projects in
   `projects.html` — update the status badge (`status-planned` →
   `status-progress` → `status-live`) and the `href` once a repo exists.

## Deploy with GitHub Pages (free, ~5 minutes)

1. Create a new GitHub repo — name it `yourusername.github.io` if you want
   it at the root of your GitHub domain, or anything else if you're fine
   with a `/repo-name/` subpath.
2. Push these files to the repo's `main` branch (root of the repo, not a
   subfolder — the HTML files reference `style.css` and `main.js` as
   siblings).
3. In the repo: **Settings → Pages → Build and deployment → Source** → set
   to "Deploy from a branch" → branch `main`, folder `/ (root)` → Save.
4. GitHub gives you a live URL within a minute or two (shown at the top of
   the Pages settings once it's built). That's your site — no server, no
   hosting bill.

## What was wrong with the old version, for reference

The previous attempt had `h1`, `h2`, and `p` all set to
`position: fixed; bottom: 50px;` — pinning all three to the exact same
spot on the screen, so they overlapped instead of flowing normally. This
version uses normal document flow (flexbox/grid) throughout, so nothing
needs manual positioning to not collide.

## Customizing further

- **Colors/fonts:** all defined as CSS custom properties at the top of
  `style.css` (`:root { ... }`) — change values there and they cascade
  everywhere.
- **Hero animation:** generated by `renderHeroScatter()` in `main.js`. It's
  a stand-in for a real UMAP/PCA plot — once you have output from an actual
  project, consider swapping it for a real exported plot.
- **Project filter tags:** pulled automatically from each card's
  `data-tags="..."` attribute in `projects.html` — add a project with a new
  tag and it appears in the filter bar with no other changes needed.
